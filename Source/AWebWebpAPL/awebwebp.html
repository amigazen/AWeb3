AWeb WebP plugin

General

The awebwebp plugin for AWeb decodes WebP images directly inside the browser, without requiring any datatype. WebP is Google's open image format used widely on the modern web; it provides better compression than JPEG and PNG and supports lossless mode and transparency.

Features:

  • Decodes both lossy (VP8) and lossless (VP8L) WebP images.
  • Full alpha-channel transparency support, rendered through a 1bpp planar mask compatible with AWeb's normal blitter path.
  • Progressive display while data is still arriving from the network.
  • Support for image scaling (the same scaling code paths as the JFIF and PNG plugins).
  • Native Picasso96 deep-bitmap rendering on RTG screens, plus fall-back to classic 8-bit planar bitmaps on AGA / ECS screens.

Manual Installation

If, for some reason, you don't want to install the plugin automatically, you can install it by hand.
  1. Copy the file awebwebp.awebplugin to a location of your choice. The recommended location for plugins like this is the awebplugin drawer in the AWeb program directory.

  2. Start AWeb, open the browser settings and bring up the Viewers page. Add an entry for MIME type image/webp with the following settings:
    • Action: "AWeb Plugin (A)"
    • Name: the location where you copied awebwebp.awebplugin
    • Arguments: leave blank or supply optional parameters, see below


  3. Don't forget to save your settings.

Parameters

The awebwebp plugin supports a few optional parameters. You can type the chosen parameters in the "Arguments:" field of the settings window. Separate the parameters by a comma or space, if you specify more than one.
PROGRESS=0|number
Specifies the number of image scan lines to decode before the display is updated. A higher number is faster but results in chunkier building of the image. PROGRESS=1 gives the smoothest progressive display but is relatively slow. The default value is 4, which is a good compromise between speed and visual attractiveness.

If you specify PROGRESS=0, progressive display is disabled. The image is not displayed until decoding is complete.

MAXMEM=number
Specifies the maximum amount of scratch memory (in kB) to be used for the decoding of each image. Large images may take quite a lot of memory during decoding. Default for this parameter is 1024 (= 1 megabyte). Note that the maximum is applied on a per-image basis, not for all images together.

LOWPRI
The LOWPRI argument will run the decoder at a lower priority than default. If you are using your Amiga for other tasks while AWeb is downloading images, this feature helps you to keep the GUI responsive when many images are being decoded.

Note that the LOWPRI argument might not be effective when you use a custom task scheduler like Executive. Use task name "AWebWEBP decoder" to configure the decoder task in custom schedulers.
